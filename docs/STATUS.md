# Status and next steps

Last updated: 2026-10-27. Everything below is saved on disk; a new session can continue from here.

## Where the data stands

- `data/raw/<district>.json`: one file per district, written by the district scouts (first collection round with the music-teaching scope). Each entity has `instruments` and `instruments_detail`, annotated from the entity's own site.
- `data/jobs.json`: generated by `scripts/merge.py`, `geocode.js` and `enrich_stations.js` (re-run them after any change to `data/raw/`).
- `dist/berlin-music-map.html`: built by `py scripts/build_map.py`.

## Done

- Scope narrowed to music teaching; categories MUN, PRV, PNO, WND, EDU, HOC, ENS, OUT and CHO (Singing & choirs layer).
- Instrument-family filter, branch markers, transit layers, email module with tip dialog, universal build with no personal data.
- Names of people and private email addresses removed from the data (see `docs/DATA-MODEL.md`).

## Decisions taken

- Schools that teach pop or percussion only (for example Modern Music School, Drumschool Berlin) stay in the data: they are useful for the instrument filter.
- A school that teaches several subjects stays in its general category; PNO, WND and CHO are for places whose main activity is that subject.
- Municipal fee conditions change every January; check `data/reference/fees.md`.
